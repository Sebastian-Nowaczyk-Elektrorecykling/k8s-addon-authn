# Hubble handoff

The base repository owns HTTPRoute `administration/administration` and its
`hubble-backend` ReferenceGrant. This add-on owns Heimdall and its configuration.
There is exactly one Hubble route and one Cilium installation.

Applying this repository installs a Cilium policy that permits only Heimdall to
reach Hubble UI. **The previous direct route stops working at that point.**
It stays closed until the base-owned route points to the ready proxy. There is
no automatic unauthenticated fallback.

After `scripts/bootstrap.sh` completes:

```bash
python3 scripts/prepare-hubble-handoff.py /path/to/minimum-k8s-net-elektro
git -C /path/to/minimum-k8s-net-elektro diff
```

The helper changes only these files in that **local** checkout:

- `config/cluster.json`: backend becomes `authn-admin/heimdall:4456`.
- `clusters/lan/cluster-settings.yaml`: generated by the base's own generator.
- `infrastructure/admin/routes.yaml`: sanitizes forwarding headers and removes
  the overall request timeout for streams.

It does not commit or push. Commit and push those three reviewed files in the
networking repository, then let its existing `admin` Flux Kustomization reconcile.
Do not put another Hubble route in this repository, suspend its existing owner,
patch the live route, or change the chart-managed `hubble-ui` Service.

The forwarding filter removes `Forwarded`, `X-Forwarded-Host`,
`X-Forwarded-Uri`, `X-Forwarded-Method`, `X-Forwarded-Path`, and
`X-Auth-Request-Redirect`, and sets `X-Forwarded-Proto: https`.
Heimdall trusts the base cluster's LAN and pod CIDRs only; its ingress policy
allows the Cilium Gateway identity. If your base CIDRs differ, update
`infrastructure/heimdall/release.yaml` before deployment.

The base repository generates the narrowly scoped ReferenceGrant in
`authn-admin` and removes its previous grant from `kube-system`.

```bash
kubectl -n administration describe httproute administration
kubectl -n authn-admin get referencegrant hubble-backend
bash scripts/check.sh
```

The route needs `Accepted=True` and `ResolvedRefs=True`. In a fresh browser,
open `https://hubble.admin.internal`, sign in, and confirm live flows keep
updating. A test that only sees a login redirect is insufficient.

Rollback should restore the last working SSO release/configuration. Restoring the
old direct backend while retaining the policy leaves Hubble unavailable. Removing
the policy as well would deliberately reopen unauthenticated access and is not
an automatic uninstall action.
